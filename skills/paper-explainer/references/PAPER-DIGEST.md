# PAPER-DIGEST.md — 论文结构化摘要（digest.md）规格

`digest.md` 是本工作流的**内容中枢**。它夹在 `paper.md`（原文）与
`script.md`（口播稿）之间，把论文拆成固定的结构：

```
论文类型 type（先判：AI_method / benchmark / clinical / 社科人文 / 综述）
  + 主要贡献与创新点（第 0 节，第一屏）
  + 前置概念 / 依赖（第 0.5 节，观众先修）
  + 7 个维度（动机 / 思想 / 设计 / 结构 / 算法 / 实验设计 / 结果）
  + 图表 / 素材清单（每张图/表/公式/原句的去向）
```

后续 outline 的信息池、章节画面的细节、SVG 重绘与原图嵌入都从这里取，
不再反复回读长原文。

> **双源原则的落点**：`script.md` 决定节奏（念什么），`paper.md` 决定
> 画面密度（屏幕上还能挂什么）。`digest.md` 是这两者的**索引**——它把
> paper 里的细节按维度归好，方便 script 和章节各自取用。

---

## 铁律

1. **可回溯**：digest 里出现的每个数字 / 结论 / 公式，都必须能在
   `paper.md` 或 arXiv LaTeX 源找到出处。找不到就不写。
2. **不编造**：论文没做的实验、没报的指标、没提的局限，一律不补。
   论文没给某个维度内容时，写 `（论文未涉及）`，不要用常识填充。
3. **区分论文声称 vs 你的解读**：作者的原话/声称用「作者称」标注；
   你的归纳用「解读：」标注。两者不能混。
4. **先判类型再填维度**：digest 开头先定 `type`（见「论文类型」节）。
   7 维的固定结构不变，但每个类型的**维度语义与边界问题不同**——
   类型判错，后面全错。
5. **贡献优先**：第 0 节「主要贡献与创新点」必须最先写、最完整。
   它是 script 的骨架：视频重点讲什么，由这里决定，而不是由论文的
   章节顺序决定。
6. **前置概念先列**：第 0.5 节把「不解释就看不懂主线」的先修概念 /
   前作列全（1–5 条），每条带一句原文定义与讲解策略。paper-to-video
   系统最常见的毛病是结构对、但从不解释前置概念——这一节就是防它。
7. **技术含量定篇幅**：每条贡献标「技术含量：高 / 中 / 低」并给理由。
   标「高」的贡献 → 更多「可上屏」条目、更多 step 预算、更细的讲解
   层次；「低」的（纯组合、调参、工程细节）一笔带过。
8. **素材先登记**：论文里的每张关键图 / 表 / 公式 / 原句，先在末尾
   「图表 / 素材清单」登记**素材策略**——`SVG 重绘` / `原图嵌入` /
   `KaTeX 公式` / `原文引用`——并注明来源（Fig/Tab/eq 编号、PDF 页、
   LaTeX 源文件）。实现时按 `PAPER-ASSETS.md` 取用。
9. **原图是合法素材**：定性图（真实照片 / 渲染结果 / 视频帧 / 定性
   对比）与复杂大图，**直接从论文取原图嵌入**（裁切干净、注明编号），
   不要硬画 SVG，也不假装复现像素；结构清晰的架构 / 流程图仍优先
   SVG 重绘（可动效、可逐步揭示）。
10. **为扩写留粒度**：可上屏条目彼此独立、一条一件事并带来源；素材清单
    的来源列写清**可复现参数**（PDF 页码 / bbox / dpi / LaTeX 源文件）。
    用户日后说「这部分展开讲」时直接从这里取料，不用重读全文。

## 论文类型（type：先判它，再填维度）

digest 开头先定一个 `type`，7 个维度按该类型的语义填。判定看标题 /
摘要的任务句、贡献类型、评测方式；拿不准按最接近的填，并注明
「类型判断存疑」。

| type | 判定信号 | 7 维重心偏移 |
|---|---|---|
| `AI_method`（默认） | 提出模型 / 算法 / 训练策略，用基准指标评测 | 标准 7 维；03–06 是主战场 |
| `benchmark_or_dataset` | 贡献是数据集 / 评测基准 / 协议 | 3 改「数据构建与标注协议」；4 改「任务与样本结构」；5 改「构建 / 筛选 / 评测流程」 |
| `clinical_or_psychology` | 样本、纳排标准、量表、统计检验 | 3 改「研究设计与分析模型」；4 改「变量与测量」；5 改「统计路径」；7 强调效应量与不确定性 |
| `humanities_or_social_science` | 材料 / 案例 / 档案 / 理论论证 | 3 改「理论框架」；4 改「材料范围与选择标准」；5 改「论证路径」；7 写解释性发现与概念贡献 |
| `survey_or_review` | 综述 / 分类体系 / 领域共识与分歧 | 3 改「分类体系与纳入标准」；4 改「方法谱系」；5 改「证据综合逻辑」；7 写共识 / 分歧 / 开放问题 |

**类型专属边界问题**（答案写进对应维度的「解读」与第 7 维「局限」）：

- `AI_method`：核心机制的收益由哪个消融支撑？结论不能外推到哪些数据 /
  算力 / 协议之外？有没有没报的失败或不稳定设置？
- `benchmark_or_dataset`：它真正测到的是什么构念、哪些只是间接近似？
  任务 / 采样 / 标注协议引入哪些覆盖缺口或偏差？
- `clinical_or_psychology`：结果支持相关、预测还是因果？样本与量表如何
  限制外推？有没有未观测混杂？
- `humanities_or_social_science`：论证依赖哪些材料与理论前提？有没有
  替代解释？哪些是概念判断而非经验事实？
- `survey_or_review`：检索与纳入标准会漏掉哪些路线？给出的是领域共识
  还是作者分类？趋势结论能否当成熟度判断？

非 `AI_method` 论文按上表换语义，不要硬套模型术语；某个维度确实不存在
时写 `（论文未涉及）`，不要用常识造一个。章节映射的微调见下一节。

## 第 0 节 · 主要贡献与创新点（必写，digest 第一屏）

从 abstract、intro 末尾的贡献列表、method 开头、conclusion 抓取。
逐条填写：

| # | 贡献（作者原话或紧贴原意的概括） | 类型 | 技术含量 | 论文依据 | 为什么（新在哪 / 难在哪 / 与已有方法的关键差别） |
|---|---|---|---|---|---|
| C1 |  | 新架构 / 新目标函数 / 新训练策略 / 新数据 / 新发现 / 系统 | 高 / 中 / 低 | §x · Fig.x · eq.x |  |
| C2 |  |  |  |  |  |

规则：

- **1–3 条**为主贡献；论文没明说的不要凑。作者列了 5 条但其中 2 条是
  增量工程，合并成一条并标「低」。
- **技术含量判断**：是否提出新的形式化 / 机制 / 训练策略？是否解决了
  非平凡矛盾（如效率 vs 精度）？是否只是模块组合 / 超参调整？
- **关系**：写一句「哪条是主贡献，哪些是支撑」——主贡献是视频的叙事
  主线。
- **权重落点**（写进 digest，供 Phase 3 用）：
  - 「高」→ script 至少 3–6 个 step；outline 允许扩章（见映射表）；
  - 「中」→ 1–3 个 step；
  - 「低」→ 一句话带过。

## 第 0.5 节 · 前置概念 / 依赖（必写，观众先修）

看懂这支视频需要先知道哪些概念 / 前作？从 related work、method 开头、
引言里「本文基于 X / 沿用 Y / 对比 Z」的句子扫。逐条填写：

| # | 概念 / 前作 | 论文中的一句定义（原文） | 与本文的关系 | 讲解策略 |
|---|---|---|---|---|
| P1 |  | 「…」（§2 · eq.1） | 本文改进它 / 直接沿用 / 对比对象 | 独立 step / 一句带过 / 不展开 |

规则：

- **只列「不解释就看不懂主线」的**，1–5 条。本文自己发明的东西不算前置
  （那是贡献，放第 0 节）；前置是论文**依赖的既有**概念 / 工作。
- 粒度按依赖本身：架构级（Transformer / ViT / diffusion）或具体工作级
  （某篇 baseline）都可以。
- **讲解策略三选一**（这里只登记，具体写法在 script 阶段）：
  - `独立 step`——核心前置，不理解它主线就断：在 03 核心思想章（或所在
    章）给它 1–2 个 step，按「是什么 → 为什么出现 → 在本文中扮演什么
    角色」讲；
  - `一句带过`——次要前置：首次出现给「中文（English）+ 一句直觉」；
  - `不展开`——默认通用技术观众已知：只用中文简称。
- **默认面向通用技术观众**，一律先按「要解释」处理；用户明确说面向同行 /
  专家时，可在 digest 备注里把公认概念改成 `不展开`。
- 每条的定义句必须能在 `paper.md` / LaTeX 源找到；找不到 → 回原文补，
  不要用常识编定义。
- 第 2 维「与已有范式的区别」和第 7 维「解读」都可从这里取参照物。

## 七个维度（digest.md 的固定结构）

7 维的顺序与编号固定；每个维度的**语义按 `type` 偏移**（见「论文类型」），
非 AI 论文按对应类型的写法填。

### 1. 动机与问题（Motivation & Problem）

- 一句话问题定义（作者要解决什么）
- 已有方法的不足（作者列的 gap / 痛点）
- 本文的切入角度（为什么现在能解 / 关键观察）
- 可上屏：`<gap 列表>`、`<一句问题陈述>`、`<一张对比示意>`

### 2. 核心思想（Core Idea）

- 一句话直觉（能用大白话讲清的那个 insight）
- 形式化陈述（如果论文给了）
- 与已有范式的区别（一句话对照）
- 可上屏：`<直觉示意>`、`<before/after 对照>`

### 3. 模型设计（Model / Method Design）

- 设计目标与约束（要满足什么性质）
- 关键设计决策列表（每条：决策 + 为什么这么选 + 替代方案）
- 损失函数 / 目标函数（完整写出，标注每一项的作用）
- 训练/推理策略要点
- 可上屏：`<决策列表（逐步揭示）>`、`<损失项拆解>`、`<公式>`

### 4. 模型结构（Architecture）

- 模块清单（每个模块：输入 → 输出 → 作用）
- 数据流（从输入到输出经过哪些模块、张量形状变化）
- 关键超参 / 维度（能画进图里的）
- 与 baseline 结构的差异点（高亮）
- 可上屏：`<架构图（SVG 重绘或原图 + 高亮）>`、`<形状标注>`

### 5. 算法流程（Algorithm）

- 步骤序列（编号，每步：做什么 + 依赖什么）
- 训练循环 vs 推理循环（分开写）
- 复杂度 / 关键循环边界
- 论文 Algorithm 伪代码原文（若有，摘录；LaTeX 源可直接复制）
- 可上屏：`<流程图（SVG 重绘，逐节点点亮）>`、`<伪代码逐行高亮>`

### 6. 实验设计（Experimental Setup）

- 数据集（名称 / 规模 / 划分 / 预处理）
- Baseline（逐个列出 + 为什么选它）
- 评价指标（定义 + 越大越好/越小越好）
- 实现细节（硬件 / 训练轮数 / 超参搜索）
- 消融实验设置（要验证哪个设计决策）
- 可上屏：`<数据集卡片>`、`<baseline 对照表>`、`<指标定义>`

### 7. 实验结果与结论（Results & Conclusion）

- 主结果（关键数字 + 提升幅度 + 相对谁）
- 消融结论（哪个设计决策贡献最大）
- 定性结果 / case study（有原图就登记原图）
- 作者承认的局限（原文）
- 解读：这个结果意味着什么 / 边界在哪
- 可上屏：`<主结果表>`、`<柱状/折线图（SVG 重绘）>`、`<消融热力图>`、
  `<定性对比原图>`

## 章节映射（论文维度 → 视频章节）

这是**默认模板**。维度不能漏，但**篇幅按贡献权重浮动**：

| 章节 | 覆盖 | step 预算 | 主视觉 |
|---|---|---|---|
| 01 · 开场钩子 | 贡献 0 + 核心数字 | 3–5 | 问题场景 / 反差数字 |
| 02 · 动机与已有不足 | 1 | 3–5（压缩） | gap 列表（逐个揭示） |
| 03 · 核心思想 | 2 + 贡献 | 4–6；核心创新在此 → 8–12 | 直觉示意 / before-after |
| 04 · 模型设计 | 3 + 贡献 | 5–8；高权重 → 10–14 | 决策列表 + 损失拆解 |
| 05 · 模型结构 | 4 + 贡献 | 4–7；高权重 → 8–12 | 架构图（SVG 或原图） |
| 06 · 算法流程 | 5 + 贡献 | 5–8；高权重 → 8–12 | 流程图 + 伪代码 |
| 07 · 实验设计 | 6 | 3–5（压缩） | 数据集卡片 + baseline 表 |
| 08 · 实验结果 | 7 | 5–8 | 主结果表 + 图表 + 消融 |
| 09 · 结论与局限 | 7 | 3–5 | 要点收束 + 局限 |

**权重规则**：

- 贡献标「高」的落点章节，允许扩到表内上限甚至更多；背景章压到下限。
- 核心创新章节（贡献所在）合计 ≥ 全片 step 的 **50%**。
- 若论文很短（workshop），可合并 04/05、07/08，但**思想、结构、算法、
  实验四块必须在**。
- **例外**：开场钩子（01）与结论收尾（09）允许更短（约 15–25s /
  3–4 step）——靠密度和停顿制造节奏，不需要凑时长。

**类型微调**（上表按 `AI_method` 设计）：

- `benchmark_or_dataset`：04/05 合并讲「数据构建 + 任务定义」，06 改
  「评测协议」，07/08 合并讲基线表现与覆盖偏差；
- `clinical_or_psychology`：07 压到下限，把 step 让给 04（设计 / 统计）
  与 08（效应量与不确定性）；
- `humanities_or_social_science`：04/05 合并为「理论框架与材料」，06 改
  「论证路径」，07 可并入 08；
- `survey_or_review`：06 不单列，合并进 03/04 讲分类体系，08 讲共识 /
  分歧 / 开放问题。
