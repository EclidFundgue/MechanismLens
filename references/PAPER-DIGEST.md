# PAPER-DIGEST.md — 论文结构化摘要（digest.md）规格

`digest.md` 是本工作流的**内容中枢**。它夹在 `paper.md`（原文）与
`script.md`（口播稿）之间，把论文拆成固定的 7 个维度，并预先标注每段
「可上屏要点 / 关键数字 / 需要的图」。后续 outline 的信息池、章节画面
的细节、SVG 重绘都从这里取，不再反复回读长原文。

> **双源原则的落点**：`script.md` 决定节奏（念什么），`paper.md` 决定
> 画面密度（屏幕上还能挂什么）。`digest.md` 是这两者的**索引**——它把
> paper 里的细节按维度归好，方便 script 和章节各自取用。

---

## 铁律

1. **可回溯**：digest 里出现的每个数字 / 结论 / 公式，都必须能在
   `paper.md` 找到出处。找不到就不写。
2. **不编造**：论文没做的实验、没报的指标、没提的局限，一律不补。
   论文没给某个维度内容时，写 `（论文未涉及）`，不要用常识填充。
3. **区分论文声称 vs 你的解读**：作者的原话/声称用「作者称」标注；
   你的归纳用「解读：」标注。两者不能混。
4. **图先登记后重绘**：论文里的每张关键图/表，先在 digest 末尾的
   「图表清单」登记（编号 + 它讲什么 + 重绘方式），章节实现时按登记
   表做 SVG。
5. **定性图（真实照片 / 渲染结果 / 视频帧）不硬画**：这类图（如
   qualitative comparison、demo 渲染、失败案例截图）无法用 SVG 忠实
   重绘，也**禁止贴论文原图**。处理方式：降级为「文字要点 + 占位框」，
   或只画其**结构示意**（例如「3 个输入 → 3 个输出」的排布），并在
   登记表标注「定性图，降级为要点」。视频里靠口播和字幕讲清楚，不假装
   复现像素。

## 七个维度（digest.md 的固定结构）

### 1. 动机与问题（Motivation & Problem）

- 一句话问题定义（作者要解决什么）
- 已有方法的不足（作者列的 gap / 痛点）
- 本文的切入角度（为什么现在能解 / 关键观察）
- 可上屏：`<gap 列表>`、`<一句问题陈述>`、`<一张对比示意>`

### 2. 核心思想（Core Idea）

- 一句话直觉（能用大白话讲清的那个 insight）
- 形式化陈述（如果论文给了）
- 与已有范式的区别（一句话对照）
- 可上屏：`<直觉示意>`、`<before/after 对照>`

### 3. 模型设计（Model / Method Design）

- 设计目标与约束（要满足什么性质）
- 关键设计决策列表（每条：决策 + 为什么这么选 + 替代方案）
- 损失函数 / 目标函数（完整写出，标注每一项的作用）
- 训练/推理策略要点
- 可上屏：`<决策列表（逐步揭示）>`、`<损失项拆解>`、`<公式>`

### 4. 模型结构（Architecture）

- 模块清单（每个模块：输入 → 输出 → 作用）
- 数据流（从输入到输出经过哪些模块、张量形状变化）
- 关键超参 / 维度（能画进图里的）
- 与 baseline 结构的差异点（高亮）
- 可上屏：`<架构图（SVG 重绘，逐模块点亮）>`、`<形状标注>`

### 5. 算法流程（Algorithm）

- 步骤序列（编号，每步：做什么 + 依赖什么）
- 训练循环 vs 推理循环（分开写）
- 复杂度 / 关键循环边界
- 论文 Algorithm 伪代码原文（若有，摘录）
- 可上屏：`<流程图（SVG 重绘，逐节点点亮）>`、`<伪代码逐行高亮>`

### 6. 实验设计（Experimental Setup）

- 数据集（名称 / 规模 / 划分 / 预处理）
- Baseline（逐个列出 + 为什么选它）
- 评价指标（定义 + 越大越好/越小越好）
- 实现细节（硬件 / 训练轮数 / 超参搜索）
- 消融实验设置（要验证哪个设计决策）
- 可上屏：`<数据集卡片>`、`<baseline 对照表>`、`<指标定义>`

### 7. 实验结果与结论（Results & Conclusion）

- 主结果（关键数字 + 提升幅度 + 相对谁）
- 消融结论（哪个设计决策贡献最大）
- 定性结果 / case study
- 作者承认的局限（原文）
- 解读：这个结果意味着什么 / 边界在哪
- 可上屏：`<主结果表>`、`<柱状/折线图（SVG 重绘）>`、`<消融热力图>`

## 章节映射（论文维度 → 视频章节）

这是**默认模板**，可按论文实际情况增删章节，但**维度不能漏**。

| 章节 | 覆盖维度 | 建议 step 数 | 主视觉 |
|---|---|---|---|
| 01 · 开场钩子 | 1（问题）+ 核心数字 | 3–5 | 问题场景 / 反差数字 |
| 02 · 动机与已有不足 | 1 | 4–6 | gap 列表（逐个揭示） |
| 03 · 核心思想 | 2 | 4–6 | 直觉示意 / before-after |
| 04 · 模型设计 | 3 | 5–8 | 决策列表 + 损失拆解 |
| 05 · 模型结构 | 4 | 4–7 | 架构图 SVG（逐模块点亮） |
| 06 · 算法流程 | 5 | 5–8 | 流程图 SVG（逐节点点亮）+ 伪代码 |
| 07 · 实验设计 | 6 | 4–6 | 数据集卡片 + baseline 表 |
| 08 · 实验结果 | 7 | 5–8 | 主结果表 + SVG 图表 + 消融 |
| 09 · 结论与局限 | 7 | 3–5 | 要点收束 + 局限 |

> 若论文很短（如 workshop paper），可合并 04/05、07/08，但**思想、
> 结构、算法、实验四块必须在**。每章 30–60s 是合理区间（见
> web-video-presentation 的 outline 规范）。
>
> **例外**：开场钩子（01）与结论收尾（09）允许更短（约 15–25s /
> 3–4 step）——它们靠密度和停顿制造节奏，不需要凑时长。上表里这两章
> 的「建议 step 数」按此理解。

## 自检（写完 digest 必须逐项过）

- [ ] 7 个维度是否都有内容，或明确标注「论文未涉及」？
- [ ] 每个数字能否在 paper.md 定位？（抽查至少 5 个）
- [ ] 作者声称 vs 我的解读是否分开标注？
- [ ] 「图表清单」是否覆盖了视频里要用的所有图？
- [ ] 「可上屏」条目是否足够具体到能直接指导章节画面？
- [ ] 有没有把「论文没做的」当成「论文做的」写进去？

不通过 → 回原文补，**不要**把问题留给 script 阶段。
