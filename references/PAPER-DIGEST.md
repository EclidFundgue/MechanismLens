# PAPER-DIGEST.md — 论文结构化摘要（digest.md）规格

`digest.md` 是本工作流的**内容中枢**。它夹在 `paper.md`（原文）与
`script.md`（口播稿）之间，把论文拆成固定的结构：

```
主要贡献与创新点（第 0 节，第一屏）
  + 7 个维度（动机 / 思想 / 设计 / 结构 / 算法 / 实验设计 / 结果）
  + 图表 / 素材清单（每张图/表/公式/原句的去向）
```

后续 outline 的信息池、章节画面的细节、SVG 重绘与原图嵌入都从这里取，
不再反复回读长原文。

> **双源原则的落点**：`script.md` 决定节奏（念什么），`paper.md` 决定
> 画面密度（屏幕上还能挂什么）。`digest.md` 是这两者的**索引**——它把
> paper 里的细节按维度归好，方便 script 和章节各自取用。

---

## 铁律

1. **可回溯**：digest 里出现的每个数字 / 结论 / 公式，都必须能在
   `paper.md` 或 arXiv LaTeX 源找到出处。找不到就不写。
2. **不编造**：论文没做的实验、没报的指标、没提的局限，一律不补。
   论文没给某个维度内容时，写 `（论文未涉及）`，不要用常识填充。
3. **区分论文声称 vs 你的解读**：作者的原话/声称用「作者称」标注；
   你的归纳用「解读：」标注。两者不能混。
4. **贡献优先**：第 0 节「主要贡献与创新点」必须最先写、最完整。
   它是 script 的骨架：视频重点讲什么，由这里决定，而不是由论文的
   章节顺序决定。
5. **技术含量定篇幅**：每条贡献标「技术含量：高 / 中 / 低」并给理由。
   标「高」的贡献 → 更多「可上屏」条目、更多 step 预算、更细的讲解
   层次；「低」的（纯组合、调参、工程细节）一笔带过。
6. **素材先登记**：论文里的每张关键图 / 表 / 公式 / 原句，先在末尾
   「图表 / 素材清单」登记**素材策略**——`SVG 重绘` / `原图嵌入` /
   `KaTeX 公式` / `原文引用`——并注明来源（Fig/Tab/eq 编号、PDF 页、
   LaTeX 源文件）。实现时按 `PAPER-ASSETS.md` 取用。
7. **原图是合法素材**：定性图（真实照片 / 渲染结果 / 视频帧 / 定性
   对比）与复杂大图，**直接从论文取原图嵌入**（裁切干净、注明编号），
   不要硬画 SVG，也不假装复现像素；结构清晰的架构 / 流程图仍优先
   SVG 重绘（可动效、可逐步揭示）。

## 第 0 节 · 主要贡献与创新点（必写，digest 第一屏）

从 abstract、intro 末尾的贡献列表、method 开头、conclusion 抓取。
逐条填写：

| # | 贡献（作者原话或紧贴原意的概括） | 类型 | 技术含量 | 论文依据 | 为什么（新在哪 / 难在哪 / 与已有方法的关键差别） |
|---|---|---|---|---|---|
| C1 |  | 新架构 / 新目标函数 / 新训练策略 / 新数据 / 新发现 / 系统 | 高 / 中 / 低 | §x · Fig.x · eq.x |  |
| C2 |  |  |  |  |  |

规则：

- **1–3 条**为主贡献；论文没明说的不要凑。作者列了 5 条但其中 2 条是
  增量工程，合并成一条并标「低」。
- **技术含量判断**：是否提出新的形式化 / 机制 / 训练策略？是否解决了
  非平凡矛盾（如效率 vs 精度）？是否只是模块组合 / 超参调整？
- **关系**：写一句「哪条是主贡献，哪些是支撑」——主贡献是视频的叙事
  主线。
- **权重落点**（写进 digest，供 Phase 3 用）：
  - 「高」→ script 至少 3–6 个 step；outline 允许扩章（见映射表）；
  - 「中」→ 1–3 个 step；
  - 「低」→ 一句话带过。

## 七个维度（digest.md 的固定结构）

### 1. 动机与问题（Motivation & Problem）

- 一句话问题定义（作者要解决什么）
- 已有方法的不足（作者列的 gap / 痛点）
- 本文的切入角度（为什么现在能解 / 关键观察）
- 可上屏：`<gap 列表>`、`<一句问题陈述>`、`<一张对比示意>`

### 2. 核心思想（Core Idea）

- 一句话直觉（能用大白话讲清的那个 insight）
- 形式化陈述（如果论文给了）
- 与已有范式的区别（一句话对照）
- 可上屏：`<直觉示意>`、`<before/after 对照>`

### 3. 模型设计（Model / Method Design）

- 设计目标与约束（要满足什么性质）
- 关键设计决策列表（每条：决策 + 为什么这么选 + 替代方案）
- 损失函数 / 目标函数（完整写出，标注每一项的作用）
- 训练/推理策略要点
- 可上屏：`<决策列表（逐步揭示）>`、`<损失项拆解>`、`<公式>`

### 4. 模型结构（Architecture）

- 模块清单（每个模块：输入 → 输出 → 作用）
- 数据流（从输入到输出经过哪些模块、张量形状变化）
- 关键超参 / 维度（能画进图里的）
- 与 baseline 结构的差异点（高亮）
- 可上屏：`<架构图（SVG 重绘或原图 + 高亮）>`、`<形状标注>`

### 5. 算法流程（Algorithm）

- 步骤序列（编号，每步：做什么 + 依赖什么）
- 训练循环 vs 推理循环（分开写）
- 复杂度 / 关键循环边界
- 论文 Algorithm 伪代码原文（若有，摘录；LaTeX 源可直接复制）
- 可上屏：`<流程图（SVG 重绘，逐节点点亮）>`、`<伪代码逐行高亮>`

### 6. 实验设计（Experimental Setup）

- 数据集（名称 / 规模 / 划分 / 预处理）
- Baseline（逐个列出 + 为什么选它）
- 评价指标（定义 + 越大越好/越小越好）
- 实现细节（硬件 / 训练轮数 / 超参搜索）
- 消融实验设置（要验证哪个设计决策）
- 可上屏：`<数据集卡片>`、`<baseline 对照表>`、`<指标定义>`

### 7. 实验结果与结论（Results & Conclusion）

- 主结果（关键数字 + 提升幅度 + 相对谁）
- 消融结论（哪个设计决策贡献最大）
- 定性结果 / case study（有原图就登记原图）
- 作者承认的局限（原文）
- 解读：这个结果意味着什么 / 边界在哪
- 可上屏：`<主结果表>`、`<柱状/折线图（SVG 重绘）>`、`<消融热力图>`、
  `<定性对比原图>`

## 章节映射（论文维度 → 视频章节）

这是**默认模板**。维度不能漏，但**篇幅按贡献权重浮动**：

| 章节 | 覆盖 | step 预算 | 主视觉 |
|---|---|---|---|
| 01 · 开场钩子 | 贡献 0 + 核心数字 | 3–5 | 问题场景 / 反差数字 |
| 02 · 动机与已有不足 | 1 | 3–5（压缩） | gap 列表（逐个揭示） |
| 03 · 核心思想 | 2 + 贡献 | 4–6；核心创新在此 → 8–12 | 直觉示意 / before-after |
| 04 · 模型设计 | 3 + 贡献 | 5–8；高权重 → 10–14 | 决策列表 + 损失拆解 |
| 05 · 模型结构 | 4 + 贡献 | 4–7；高权重 → 8–12 | 架构图（SVG 或原图） |
| 06 · 算法流程 | 5 + 贡献 | 5–8；高权重 → 8–12 | 流程图 + 伪代码 |
| 07 · 实验设计 | 6 | 3–5（压缩） | 数据集卡片 + baseline 表 |
| 08 · 实验结果 | 7 | 5–8 | 主结果表 + 图表 + 消融 |
| 09 · 结论与局限 | 7 | 3–5 | 要点收束 + 局限 |

**权重规则**：

- 贡献标「高」的落点章节，允许扩到表内上限甚至更多；背景章压到下限。
- 核心创新章节（贡献所在）合计 ≥ 全片 step 的 **50%**。
- 若论文很短（workshop），可合并 04/05、07/08，但**思想、结构、算法、
  实验四块必须在**。
- **例外**：开场钩子（01）与结论收尾（09）允许更短（约 15–25s /
  3–4 step）——靠密度和停顿制造节奏，不需要凑时长。

## 自检（写完 digest 必须逐项过）

- [ ] 「主要贡献与创新点」是否明确？1–3 条，每条有论文依据、有技术含量分级与理由？
- [ ] 主贡献 / 支撑贡献的关系是否写明？
- [ ] 技术含量「高」的贡献是否拿到更多可上屏条目与 step 预算（对照映射表）？
- [ ] 7 个维度是否都有内容，或明确标注「论文未涉及」？
- [ ] 每个数字能否在 paper.md / LaTeX 源定位？（抽查至少 5 个）
- [ ] 作者声称 vs 我的解读是否分开标注？
- [ ] 「图表 / 素材清单」是否覆盖视频里要用的所有图、表、公式、原句，并写明策略与来源？
- [ ] 原图素材是否标注了 Fig/Tab 编号，路径是否指向 `assets/` 或 `paper-src/`？
- [ ] 「可上屏」条目是否足够具体到能直接指导章节画面？
- [ ] 有没有把「论文没做的」当成「论文做的」写进去？

不通过 → 回原文补，**不要**把问题留给 script 阶段。
